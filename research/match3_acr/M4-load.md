# M4 进程内并发复测

复用 M2 的实际 `choose_refill` 在线决策和冻结证书库。对照 Witness、Fixed-1、Fixed-6、ACR。每条请求都是来自四种配方的真实起始状态或证书后继状态及一个固定合法交换。同一场景、同一轮次的请求序列和提案种子在各控制器间一致。ACR 的尝试次数查询在计时范围内。

每个工作线程一条 128 项容量的 FIFO。一个开放环生产线程按 100 微秒时间片投递，依次将请求分给 1、4 或 8 个工作线程。队列满时拒绝本次请求，已进入队列的请求完成后再结束计时。每个场景、缓存条件和控制器各跑两轮。

| 场景 | 工作线程 | 计划请求／秒 | 每轮请求 |
| --- | ---: | ---: | ---: |
| 单线程 | 1 | 5,000 | 3,000 |
| 四线程 | 4 | 20,000 | 6,000 |
| 八线程 | 8 | 40,000 | 12,000 |
| 四线程高压 | 4 | 160,000 | 20,000 |
| 八线程高压 | 8 | 320,000 | 24,000 |

`ColdNoMemo` 每次决策从不可变证明库查找。`Warm` 每个工作线程为每个棋盘维持独立在线缓存，预热请求使用独立种子，排除在计时外。各控制器之间不共享在线缓存。

单次 CPU 时间用 `CLOCK_THREAD_CPUTIME_ID`。服务墙钟时长从取出请求到返回，排队从入队到开始服务，端到端从计划到达到完成。另计实际投递与计划到达的偏差。吞吐的时长分母涵盖投递和排空。`decision_cpu_cores` 只统计决策所占 CPU，生产者与队列的开销计在实际墙钟中。`witness_uses` 包括直接执行见证的请求，`witness_fallbacks` 只统计有尝试预算但失败的回退。

获取在线耗时的环境为 Ubuntu WSL2、GCC 16.2 Release、Ryzen 7 5800X。进程绑在 vCPU 8–15，对应四个物理核的八个 SMT 线程。结果描述单机进程内、已预加载的路径。实际服务器还应测量通信、序列化、调度和部署环境下的资源共享。

## 实测

16 局覆盖了 167 个证书状态与交换组合。80 个实验单元共投递 1,040,000 次请求，完成 946,941 次，队列满拒绝 93,059 次。全部完成请求通过验证，588,958 次执行自然补充。七次用时超过 2 ms 的软 CPU 预算，五次触发内部限时回退，离散工作预算超限为零。

| ACR 热缓存场景 | 决策 CPU P99，两轮范围 | 排队 P99，两轮范围 | 到达到完成 P99，两轮范围 | 每轮拒绝数 |
| --- | ---: | ---: | ---: | ---: |
| 单线程 | 35.99–39.05 µs | 34.40–42.39 µs | 148.54–149.22 µs | 0 |
| 四线程 | 33.38–33.87 µs | 32.57–33.33 µs | 177.27–179.90 µs | 0 |
| 八线程 | 30.73–31.91 µs | 29.48–29.88 µs | 189.41–194.40 µs | 0 |
| 四线程高压 | 27.20–30.70 µs | 107.29–127.76 µs | 274.49–312.53 µs | 0 |
| 八线程高压 | 30.57–37.22 µs | 2.950–3.193 ms | 11.739–13.183 ms | 2,835–4,177 |

计划 40,000 请求／秒的热缓存场景中，两轮 ACR 均完成 12,000 个请求，实测吞吐约 39,945–39,950 请求／秒。该场景 Fixed-6 的决策 CPU P99 为 33.63–33.89 µs。计划 320,000 请求／秒的压力场景中，生产者投递偏差和排队同时扩大，ACR 每轮有效吞吐约 240,814–259,451 请求／秒。
