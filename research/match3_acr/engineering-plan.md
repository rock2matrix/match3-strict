# ACR v1.0 最终工程研发计划

ACR 在 Strict 证书闭包内改变自然补充的尝试预算。决策按 Balanced、失败回退已认证见证、Hybrid 架构执行。现有 120 局继续绑定固定见证与 `strict-random-tier-v1`。

## 设计与安全边界

| 工程面 | 实现 |
| --- | --- |
| 离线 | 验证原始 Strict 证书。在独立的自然提案流中发现可用续局，保存精确后继及完整已验证证书。再用独立抽样审计冻结支持集，按棋盘与状态类型计算 Wilson 下界。 |
| 在线 | 读取权威状态，验证并定位已有见证。用该状态类型的统计选 `K`，对自然提案查精确后继并独立回放。只有安全终态或有已证续局的稳定后继可执行。提案耗尽或预算触发时执行原见证。 |
| 版本 | 规则、调色板、初始棋盘、目标、剩余步数、证书、支持集构建规则、补充控制器和易度标准按版本绑定。线上查表条件需要完整匹配。 |
| 缺失与未决 | 冻结库未命中是未决。可执行的固定见证由当前证书提供。入口证书失效时拒绝本次处理并由上层恢复至有效的权威状态。 |

每条自然提案是整个交换的连锁轨迹。每波按原有整数配额随机生成均匀排列。概率质量按完整轨迹定义，同一个稳定后继可以由多条轨迹到达。本原型把已证后继索引与可回放的原见证放在内存，离线构建后只读。它使用内嵌 WSL 负载驱动测控制器，线上持久化、跨进程版本切换和真实服务调度另需集成验证。

对固定状态与交换，令 `z` 为自然提案落入已证集合的概率。固定支持集、独立且同分布、预算充足时，`K` 次首个成功策略的回退概率为 `(1−z)^K`，平均抽样次数为 `[1−(1−z)^K]/z`。`z=0` 时平均次数为 `K`。当 `K≥1`，输出相对自然分布的完整轨迹 TV 在同一支持集上为 `1−z`。增大 `K` 主要减少见证回退、改变支持集内的概率分配。例：目标回退 5% 下，`z=.6` 要 4 次，`z=.9` 要 2 次。

动态规划用已证安全质量的单侧 95% Wilson 下界 `Z_L`。先选预测能达到 5% 回退目标的最少尝试次数。目标不可达时，使用冻结的 Balanced 权重，按 `.35×TV估计 + .20×预期抽样次数/6 + .45×回退概率` 比较可选方案。以站内实测 CPU 另行验证，Wilson 只给抽样状态组提供预算预测；未知、超时及组间差异都不产生安全证明。

每次决策最多 6 次自然提案，候选检查、补充工作量、稳定后继检查上限分别为 512、8192、128。线程 CPU 软预算为 2 ms，提案前后检查，超预算时即便刚获得安全结果也回退。同步原子操作与线程被调度出去仍可能造成延迟超过 2 ms。样本下的 P99 与硬实时服务保证分别评估。

## 里程碑与验收

| 里程碑 | 本轮执行 | 通过条件或决策依据 |
| --- | --- | --- |
| M1 安全质量统计 | 原 200 局，每局沿证书与 4 种代理生成离线续局。冻结库后独立审计，按首波是否达标、末步与剩余步数压力分组。 | 输出安全／不安全／未知的完整计数、Wilson 下界和稀疏组来源。统计口径绑定各级版本。 |
| M2 ACR v1.0 | 实现数值规划、在线预算、自然提案、精确后继查表、首个证实安全的提案、见证回退。 | 每个准入自然轨迹独立回放，全部续局有证明。检查次数上限守恒。单元验证概率和 `K` 边界。 |
| M3 控制器比较 | 固定见证、固定 1／3／6 次及 ACR。相同 200 局、四代理、每组合 64 次，冷／热缓存分开。 | 相对固定 6，预先设定的试用门槛为每回合平均 CPU 节省至少 10%、回退增加不超过 2 个百分点、线程 CPU P95 不超过 2 ms。Strict 完成与证明回放全通过。 |
| M4 并发预算 | 使用同一批已认证状态与交换，向本地有界队列按固定速率投递，测不同工作线程数, 观察过载。 | 记录接纳、拒绝、完成吞吐、排队与执行 P50/P95/P99、线程 CPU、预算触发和安全执行计数。用实际服务负载补做部署验收。 |
| M5 重校准 | 保留 V1。用原 100 局在 ACR 下锁定新切点，再用另一批 200 局检查，后者独立于 M3。 | 逐配方分档、跨代理秩相关和与见证版档位迁移可追溯。模型绑定 ACR 版本，作为研究候选。 |

四类正式对照为见证、固定 1、固定 6、ACR。固定 3 是计算成本与回退曲线的加测对照。各控制器共用同一个只读证明库，但查找缓存隔离。完整对局使用相同代理规则与编号随机流。不同补充可能导致后续棋盘不同。M4 固定完全相同的状态与动作，以单请求结果补充整局对照。

首波颜色 TV 在补充格数与位置条件下测量。首波顺序 TV/KL 对比同配额均匀排列，并报告有限样本的均匀参考误差。全轨迹结论依据固定支持集上的概率模型及实际回退计数。首波测量明确覆盖首波。

## 推进顺序

本轮只实现 ACR v1.0。先看固定 6 的 paired CPU、回退和线上闭包风险，再判断是否进入真实服务集成。成本感知的离线缓存排序与泛化概率模型属于后续版本。正式给玩家提供档位之前需要真人校准与服务容量验证。
